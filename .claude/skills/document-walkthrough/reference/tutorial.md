# Tutorial skeleton (learning-oriented)

The single, hand-held, zero-to-first-success path. **One route, no choices, can't fail.** System- and
language-agnostic — fill from the real surface. The writer owns the reader's success.

```
# Getting started with <Product> — your first <win>

> In this tutorial you'll <do one concrete thing> and see <the visible result>. By the end you'll
> have <the first success>. No prior experience needed.

## Before you start
- <exact tool/version to install>           ← a checklist; the reader verifies each yes/no
- <account / access, if any>
- About <N> minutes

## Step 1 — <verb the first action>
<exactly what to do, where to type it>

    <the exact command / tool call>

You should see:

    <the exact observable output>

## Step 2 — <verb the next action>
…  ← one action per step; after every step, a "You should see:" block

## You did it
You've <restated first success>. <One sentence on what just happened, so it makes sense.>

## Next steps
- To <next natural task> → see the how-to: <link>
- Full command reference → <link to the reference manual>
```

## Rules (what makes a tutorial pass)

- **One path, zero choices.** No "if you prefer…", no alternatives, no branches. Remove every fork —
  the beginner cannot judge between options.
- **Can't fail / safe to restart.** Use a throwaway/clean starting state; a beginner who messes up can
  start over with no damage. If a step *can* fail, pre-empt it or remove it.
- **A "You should see:" after every step.** This is how the beginner knows they're on track — it is the
  difference between a tutorial and a list of commands.
- **Explicit about the basics.** Where to type, what to install, what each step *does* — assume they may
  not know what to ask.
- **Concrete and particular.** Real commands, real output, a real first result — never "configure your
  environment appropriately".
- **One first success.** A tutorial teaches *one* complete first journey, not every feature. Resist
  scope creep; extra goals are how-to guides.
- **Recap + next steps.** End by naming what they achieved and pointing onward (to how-tos / reference).
